## 3. Known Limitations Going Into Milestone 2

1. **Synthetic data ceiling** — current data is generated by a formula (rush-hour multiplier + random noise), not real sensors. A trained model's usefulness will be capped by how realistic this generator is.
2. **No cross-road effects** — each road's data is generated independently; real traffic has spillover effects between connected roads not represented here.
3. **Fixed-threshold "ground truth"** — since `congestion_level` in the data is itself rule-based, training directly against it risks a model just re-learning the same threshold rule rather than discovering new patterns.
4. **Gateway is a minimal demo** — `gateway.py` only routes to this one service; the real Gateway (Intern 1's ownership) will need to add Auth and Prediction routing before end-to-end system integration is complete.
5. **No production deployment** — as required by the SRS, no deployment activity of any kind has occurred. Everything runs locally via Docker Compose / local processes only.

## 4. Recommended Next Steps for Milestone 2

1. **Extend the synthetic data generator** (or begin real sensor integration) to include day-of-week effects, occasional simulated incidents, and road-type-based baseline differences — giving a trained model genuinely learnable signal beyond the current rush-hour pattern
2. **Build the real ML training pipeline** using the suggested features documented in `M2_Historical_Data_Feed_Documentation.md`
3. **Replace the heuristic stub** behind the Gateway with the trained model's real prediction endpoint, keeping the same response contract so the frontend doesn't need to change
4. **Re-run `final_smoke_test.py`** after any schema or endpoint changes to confirm nothing in this module broke
