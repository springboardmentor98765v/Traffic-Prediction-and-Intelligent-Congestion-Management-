# Pull Request Review Checklist

## PR Information

- [ ] Title clearly states the purpose and scope.
- [ ] Description includes problem statement, changes, and validation steps.
- [ ] Related issue or task link is included.

## Code Quality

- [ ] Code follows project style and naming conventions.
- [ ] No dead code, commented-out blocks, or debug statements remain.
- [ ] Error handling is implemented where required.
- [ ] Security-sensitive inputs are validated.

## Testing

- [ ] Relevant unit tests added or updated.
- [ ] Regression tests included if bug fix is involved.
- [ ] Manual QA steps recorded where automation is not available.
- [ ] Test results included in PR notes.

## Documentation

- [ ] User-facing docs or config notes updated if needed.
- [ ] API contract or schema changes documented.

## Final Approval

- [ ] CI checks passed.
- [ ] Required approvals received.
- [ ] No blocking defects remain.
- [ ] Change is safe to merge into the target branch.
