# Pull Request Checklist

## Code Quality

- [ ] Code follows the project's coding standards.
- [ ] Code is properly formatted.
- [ ] No unnecessary files or changes are included.
- [ ] No debug statements or temporary code remain.
- [ ] Static analysis checks pass.

## Testing

- [ ] Relevant tests have been added or updated.
- [ ] Existing tests pass.
- [ ] New functionality has been tested.
- [ ] Regression impact has been considered.

## Backend and API

- [ ] API changes are documented.
- [ ] Request validation is implemented.
- [ ] Error handling is implemented.
- [ ] Authentication and authorization are verified where applicable.

## Security

- [ ] No passwords, API keys, tokens, or secrets are committed.
- [ ] User input is validated.
- [ ] Protected endpoints enforce authorization.

## Documentation

- [ ] README/documentation is updated if required.
- [ ] Configuration changes are documented.
- [ ] Breaking changes are clearly mentioned.

## Review

- [ ] PR has a clear title.
- [ ] PR description clearly explains the changes.
- [ ] Related issue/task is referenced.
- [ ] CI checks pass.
- [ ] Required reviewer approval is obtained.
