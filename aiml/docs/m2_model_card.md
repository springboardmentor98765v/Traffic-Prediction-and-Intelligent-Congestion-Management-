# Milestone 2 Model Card

## Model

- Version: `ml-v2`
- Task: four-class congestion prediction (`LOW`, `MEDIUM`, `HIGH`, `SEVERE`)
- Estimator: scikit-learn preprocessing pipeline with one-hot road encoding and a balanced Random Forest classifier with 200 trees
- Artifact: `models/congestion_model.joblib`
- Training dataset: `data/external/traffic_readings_export.csv`
- Training command: `venv311\\Scripts\\python.exe scripts\\train_model.py`

## Features

`road_id`, `vehicle_count`, `average_speed`, Data Engineering `density`, hour, day of week, peak-hour flag, and a shifted rolling recent-congestion signal.

The Data Engineering label `MODERATE` is normalized to `MEDIUM`. `SEVERE` remains a separate class.

## Evaluation

The artifact records a chronological 80/20 holdout: 32,256 training rows and 8,064 test rows from 40,320 Data Engineering records. The export covers five roads at five-minute intervals from 2026-08-22 through 2026-09-18. These metrics are not a production-readiness claim because the data is synthetic. The forest uses parallel tree fitting (`n_jobs=-1`).

## Service behavior

- `GET /predict/congestion` returns the existing response contract with `model_version: ml-v2`.
- `GET /predict/peak-hours` returns the documented morning and evening windows.
- `GET /predict/delay` estimates delay against a 50 km/h free-flow speed using congestion multipliers of 1.0, 1.35, 1.8, and 2.2 for Severe.
- `POST /route/rank` ranks candidate routes by base duration plus predicted congestion delay.

## Limitations and next data

The dataset is generated/synthetic, labels are generated by Data Engineering rules, and there are no incident/weather fields or true travel-time targets. Validate labels against real observations, replace delay multipliers with observed travel times, and calibrate confidence before production use.
