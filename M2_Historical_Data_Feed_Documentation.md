## 1. Purpose of This Document

Milestone 1 only used a **heuristic (rule-based) stub** for congestion prediction. Milestone 2 will replace that with a **real trained ML model**. This document describes exactly what data is available, its structure, and its current limitations — so Milestone 2 planning can start from an accurate picture instead of assumptions.

## 2. Where the Data Lives

**Database:** PostgreSQL, database name `trafficvision`
**Main table:** `traffic_readings`
**Supporting tables:** `roads`, `sensors`

### `traffic_readings` — Full Column Reference

| Column | Type | Description |
|---|---|---|
| `reading_id` | BIGSERIAL | Unique ID per reading |
| `road_id` | INT | Foreign key → `roads.road_id` |
| `sensor_id` | INT | Foreign key → `sensors.sensor_id` |
| `vehicle_count` | INT | Number of vehicles detected in the interval |
| `avg_speed_kmph` | NUMERIC(5,2) | Average vehicle speed |
| `density` | NUMERIC(5,2) | Normalized traffic density (0–100 scale) |
| `congestion_level` | VARCHAR(20) | LOW / MODERATE / HIGH / SEVERE (rule-based, see Section 4) |
| `recorded_at` | TIMESTAMP | When the reading was taken |

### `roads` — Reference Data
`road_id`, `road_name`, `area`, `road_type`, `length_km`, `lanes`

---

## 3. Data Volume & Frequency (Milestone 1)

- Readings are generated **every 5 seconds, per road** by `ingest_live_data.py`
- Currently **5 sample roads** are configured (can be expanded)
- All data is **synthetic** — generated by a script, not from real sensors
- No real seasonal, weekly, or event-based patterns exist yet — only a simple rush-hour multiplier (higher density at 8–9 AM and 6–7 PM)

**Implication for Milestone 2:** the current dataset is suitable for testing a model's *pipeline* (data loading, feature extraction, training loop) but NOT for learning genuinely predictive real-world patterns, since the "ground truth" itself was generated by a simple formula, not real traffic behavior.

---

## 4. How `congestion_level` Is Currently Calculated (Heuristic Baseline)

```python
def calculate_congestion_level(density):
    if density < 30:   return "LOW"
    elif density < 60:  return "MODERATE"
    elif density < 85:  return "HIGH"
    else:                return "SEVERE"
```

This is a simple threshold rule — useful as a baseline to compare a trained model against, but not something to reproduce as "the answer" during training. A real model should learn patterns a fixed threshold can't capture (e.g., how density interacts with time of day, road type, or weather).

## 5. Suggested Features for Milestone 2 Model Training

Based on what's currently available in the schema:

| Feature | Source | Notes |
|---|---|---|
| `density` | `traffic_readings.density` | Primary signal |
| `avg_speed_kmph` | `traffic_readings.avg_speed_kmph` | Inversely related to density currently (derived, not independent) |
| `hour_of_day` | Extracted from `recorded_at` | Currently drives the rush-hour multiplier in synthetic data |
| `day_of_week` | Extracted from `recorded_at` | Not yet used in synthetic generation — real data would likely show weekday/weekend differences |
| `road_type` | `roads.road_type` | arterial / highway / local — may correlate with baseline congestion patterns |
| `lanes` | `roads.lanes` | Relevant for the utilization calculation (Day 4) |
| Recent history (lag features) | Previous N readings for the same road | Congestion is time-dependent; a model likely needs to see recent trend, not just current density |

## 6. Known Limitations to Flag for Milestone 2 Planning

1. **Synthetic data ceiling** — the model can only ever be as good as the assumptions baked into the generator (simple rush-hour multiplier + random noise). Real model value will require either real sensor data or a much more sophisticated simulator.
2. **No external factors** — weather, accidents, road closures, and special events aren't represented at all.
3. **Independent roads** — the current generator treats each road independently; real traffic has spillover effects between connected roads that aren't modeled.
4. **Fixed thresholds as "ground truth"** — since `congestion_level` is currently rule-based, training a model to predict it risks just re-learning the same threshold rule instead of discovering genuinely new patterns.

## 7. How to Query Historical Data for Training (Example)

```sql
SELECT road_id, vehicle_count, avg_speed_kmph, density, congestion_level, recorded_at
FROM traffic_readings
WHERE recorded_at >= NOW() - INTERVAL '24 hours'
ORDER BY road_id, recorded_at ASC;
```

For a Python/pandas workflow:
```python
import pandas as pd
import psycopg2

conn = psycopg2.connect(dbname="trafficvision", user="postgres", password="...", host="localhost")
df = pd.read_sql("SELECT * FROM traffic_readings ORDER BY recorded_at ASC;", conn)
```
